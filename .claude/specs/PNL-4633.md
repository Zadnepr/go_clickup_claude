# Уточнённое ТЗ: PNL-4633 «Монитор getstatus local»

## Контекст (из описания задачи)

При миграции очереди обновления статусов заказов с MySQL на Kafka из суперадминки был убран монитор, отслеживающий эту очередь. Мониторинг остался только на стороне Datadog. Неправильно настроенный Datadog-монитор не сработал на накопление очереди во время инцидента, что привело к простою обновления статусов заказов на ~2 часа. Обновление статусов заказов — одна из ключевых функций продукта, поэтому автор задачи (Dmitrii Begal) считает нужным продублировать мониторинг.

## Требования

| № | Требование | Статус | Источник |
|---|-----------|--------|----------|
| 1 | Вернуть в суперадминку монитор, отслеживающий обновление статусов заказов (`getstatus`), убранный при миграции очереди с MySQL на Kafka | база | описание |
| 2 | Дополнительно настроить внешний мониторинг обновления статусов заказов через Site24x7 (site24), независимо от Datadog | база | описание |
| 3 | Монитор должен обнаруживать накопление очереди/простой обновления статусов заказов (сценарий инцидента: простой ~2 часа из-за не сработавшего Datadog-монитора) | база (неявное нефункциональное требование) | описание |
