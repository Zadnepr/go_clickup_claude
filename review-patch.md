# Патч: контракт вердикта для команды `/review-go`

`.claude/commands/review-go.md` в этом репозитории уже содержит контракт
вердикта, описанный ниже — патчить его не нужно. Этот файл остаётся как
инструкция на случай, если вы замените `/review-go` на собственную команду
без этого раздела: сервис распознаёт итог ревью **не читая текст
замечаний**, а разбирая последнюю строку вида `ИТОГ: ...` в выводе
`claude -p`. Чтобы это работало, добавьте в конец своей команды требование
печатать эту строку последней.

Файл `review-go.md` этим сервисом не переписывается — примените изменение сами,
как посчитаете нужным вписать его в существующую структуру команды.

---

## Что добавить

В самый конец промпта команды `/review-go`, после всех инструкций по
формированию текста ревью, добавьте раздел:

```markdown
## Контракт вердикта (обязательно)

После полного текста ревью выведи **последней строкой** вывода, без какого-
либо текста после неё, строку строго следующего формата:

ИТОГ: критичных=<N> важных=<N> минор=<N> статус=<pass|fail|blocked>

Где:
- `критичных`, `важных`, `минор` — целые неотрицательные числа, количество
  замечаний соответствующего уровня серьёзности, найденных в этом ревью.
- `статус`:
  - `pass` — критичных замечаний нет.
  - `fail` — есть хотя бы одно критичное замечание.
  - `blocked` — ревью не удалось выполнить содержательно: не нашлась ветка
    или PR, недоступно ТЗ задачи, не удалось получить диф, или другая
    причина, по которой сравнение кода с требованиями не состоялось.
    `blocked` — это не то же самое, что «замечаний нет»: числа в этом случае
    можно проставить нулями, а причину блокировки описать в тексте ревью
    выше.

Строка обязана начинаться ровно с `ИТОГ: ` (с пробелом после двоеточия) и
быть последней непустой строкой всего вывода. Внешний сервис автоматизации
разбирает её регулярным выражением и не читает остальной текст ревью для
принятия решения — если строка отсутствует или не соответствует формату,
прогон будет автоматически считаться `blocked`.
```

## Пример корректного финала вывода

```
...
### Итоговая оценка

Найдено одно критичное замечание (SQL-инъекция в фильтре поиска) и два
важных замечания по обработке ошибок. Минорных замечаний нет.

ИТОГ: критичных=1 важных=2 минор=0 статус=fail
```

## Проверка

После применения патча убедитесь, что:

- строка `ИТОГ: ...` действительно последняя в выводе (после неё нет даже
  пустых строк с пробелами — сервис берёт **последнее** вхождение, но лишний
  текст после него не критичен, а вот полностью пустой финал недопустим);
- числа — целые без пробелов внутри (`критичных=1`, а не `критичных= 1`);
- значение `статус` — одно из `pass`, `fail`, `blocked`, без иных вариантов
  и без заглавных букв.
